# Full architecture audit: Java+MySQL vs Python+SQLite

Generated by `tools/architecture_audit.py` from `output/jar-inventory.json`, the MySQL schema dump, `Server-v1/game/protocol.py` and `Server-v1/db.py`. Re-run after changing either server; do not edit the counts by hand.

"Dispatched" means a `CMD_*` constant is routed in `protocol.py`. It does not mean the behaviour matches Java; see [java-python-parity-audit.md](java-python-parity-audit.md) for behaviour.

## Architecture layers

| Layer | Java + MySQL | Python + SQLite | Status |
|---|---|---|---|
| Web login/session | Apache httpd + PHP5 module (`output/orig-stack/httpd.conf`) | `Server-v1/web.py` on `http.server`, PBKDF2 passwords, SQLite sessions | Partial; see parity audit |
| Game socket | Java game server (`com.xianling.bus.client`, `com.xianling.io`); transport class not verified from bytecode | `Server-v1/server.py` `ThreadingTCPServer`, one thread per connection | Framing and key exchange match captures |
| Persistence | MySQL 5.1.37 through iBATIS accessors (`com.kernel.data`, `IIBatisDatabaseAccessor`) | SQLite via `sqlite3` in `Server-v1/db.py`, one lock per Store | Only 23 SQLite tables (13 mapped from MySQL); see table section |
| Config data | AMF3 `.jat`/`.mm` read through BlazeDS `Amf3Input` (`game-data-inventory.md`) | Own AMF3 codec `game/amf3.py` + loaders in `game/config.py` | Decodes all 218 `.jat`; see game-data inventory |
| Scheduling | Quartz scheduled jobs (`com.xianling.global`) | Mirror in `game/scheduler.py` (heartbeat, schedule map, quartz cron, token runnables) + 1s server tick driving `Session.tick()` | Partial: timed stage pushes flow; per-monster stagger still single-clock |
| Event bus / services | Event service and ~90 ServiceImpl classes per large family (`com.xianling.eventservice`) | `game/eventbus.py` EventCenter mirror (per-session via `Session.publish`); inner tokens dispatch in `tick()` | Partial: bus exists, no call sites publish yet |
| Cross-server | kuafu and messageswap (`com.xianling.bus.kuafu`, `com.xianling.messageswap`) | None | Out of scope for single-server play |
| Auth on game socket | MD5 of uid + key + timestamp (parity audit, security section) | Same legacy sign, kept for client compatibility | Replay-prone; keep behind a trusted boundary |
