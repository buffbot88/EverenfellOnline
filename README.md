# MonkeyKingOnline (DNTG / 大闹天空 "TonNgoKhong")

A preservation/revival project for **MonkeyKingOnline**, a 2014-era Chinese 2D MMO.
Goal: keep the original Flash client running (Flash is EOL) and replace the
Windows-only Java server + PHP/MySQL stack with a portable Python server. The
end goal is a **downloadable desktop client**.

## Layout

| Path | Purpose |
|---|---|
| `Server-v1/` | Python (stdlib + SQLite, Pillow for captcha only) replacement for the game server and web API. `server.py` entry; `game/` (protocol, AMF3, cipher, config); `auth.py`, `db.py`, `web.py`; `tests/`; `data/mko.db` (runtime, not source). |
| `MKO_Client/` | Original Flash client assets; the Adobe Flash Player projector target (`MKO_Client/flash-projector/flashplayer363.exe`). |
| `tools/` | Projector launcher, MySQL→SQLite migrator, and reverse-engineering helpers (`javap.py`, `decode-tap.py`, `game_data_survey.py`, `jar_inventory.py`, `architecture_audit.py`, …). |
| `docs/` | Wire evidence and port tracking: `protocol.md`, `boot-chain.md`, `server-roadmap.md`, `command-ledger.md`, `java-python-parity-audit.md`, `mysql-to-sqlite-migration.md`, `game-data-inventory.md`. |
| `reference/TonNgoKhong/` | Legacy game distribution (Java jar, bundled JRE, ESSamp Apache/PHP/MySQL). Behavioral oracle; do not modify binaries. |
| `brain/` | Project memory (decisions, constraints) maintained with the `brain` skills in `skills/` — it tracks development, it is not the project itself. |
| `skills/` | Agent skills: `brain-*` memory skills plus vendored `ui-ux-pro-max` design intelligence. |
| `agents.json` | Skill/agent registry: paths, when-to-use, and the brain + ui-ux-pro-max co-use rule. |

## Quickstart

**Python server** (from `Server-v1/`):

```sh
python3 server.py --db data/mko.db --game 127.0.0.1:8008 --web 127.0.0.1:8080
python3 -m unittest discover -s tests   # server tests (837, all pass)
```

**Tools tests** (from `tools/`): `python3 -m unittest discover -s tests` (44 tests).

**Legacy data** (from the repo root; MySQL is only read):

```sh
python3 tools/migrate_mysql_to_sqlite.py --users stress   # copy one account's rows
```

**Projector launch** (needs the Python server running):

```sh
python3 tools/projector-client.py <user> <password> --api-base http://127.0.0.1:8080 --dry-run
```

## Architecture

```text
Flash projector (flashplayer363.exe) running Main.swf
 ├─ /res/*            → legacy res tree, served locally
 ├─ HTTP account API  → Server-v1 web API on 127.0.0.1:8080
 └─ game socket       → Server-v1 TCP on 127.0.0.1:8008 (native, no bridge)
```

1. client → `u32be(len) + AMF3 "INITKEY"`; server → plaintext key.
2. client → **encrypted** AMF3 command frames (`SimpleEncrypt`).
3. server → **plaintext** AMF3 replies (the server never encrypts).

Every command id maps to a Java class in `docs/java-command-map.md`. Port status:
122 of 879 ledger IDs routed (109 persisted), tracked in `docs/command-ledger.md`
— regenerated by `tools/architecture_audit.py`, never hand-edited.

## Rules

- The Java server is the behavioral oracle: port from bytecode, never invent numbers, golden-test everything.
- Auth sign is HMAC-SHA256 (`MKO_SIGN_SECRET`, 300s window); legacy MD5 is rejected. Do not expose the server to the internet.
- Passwords are PBKDF2; the legacy stack's plaintext must not return.
- Keep docstrings to 1–2 sentences. Run the tests before declaring changes done.
- Full context lives in [knowledge.md](knowledge.md); development rules in [VOWS.md](VOWS.md).
